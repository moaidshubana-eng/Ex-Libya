# 10 — النشر والتدريب

## 1. بيئة الإنتاج المقترحة

| المكون | المواصفات الدنيا | ملاحظات |
|---|---|---|
| خادم التطبيق | 2 vCPU، 4GB، Ubuntu 24.04 LTS | نسختان من التطبيق (Docker أو systemd) خلف Nginx |
| قاعدة البيانات | 2 vCPU، 8GB، SSD 100GB | PostgreSQL 16، خادم منفصل، شبكة خاصة، أرشفة WAL |
| التخزين الكائني | S3 أو MinIO | صور السيارات والمستندات |
| النسخ الاحتياطي | موقع ثانٍ (مدينة أخرى أو سحابة) | تشفير قبل النقل |
| النطاق والشهادة | Let's Encrypt | تجديد آلي |
| بيئة ما قبل الإنتاج (Staging) | نسخة مصغرة | بيانات مُقنّعة من الإنتاج لاختبار الإصدارات |

**الاستضافة:** مزود قريب جغرافيًا (أوروبا الجنوبية) لزمن وصول جيد من ليبيا، أو خادم محلي مع اتصال احتياطي. إذا كانت الاستضافة محلية، يُضاف مولّد ومزود إنترنت ثانٍ، لأن انقطاع الاتصال أثناء مزاد حي يقطع المزايدين.

### 1.1 خطوات النشر الأولى

```bash
# على خادم قاعدة البيانات
createuser auction_app --pwprompt
createdb car_auction --owner auction_app

# على خادم التطبيق
git clone <repo> && cd car-auction
cp .env.example .env    # املأ DATABASE_URL والمفاتيح (openssl rand -base64 32) وعطّل MOCK_FEEDS
npm ci --omit=dev
psql "$DATABASE_URL" -f db/schema.sql           # مرة واحدة فقط على قاعدة فارغة
docker build -t car-auction .                  # أو: node src/server.js تحت systemd
docker run -d --env-file .env -p 4000:4000 --restart unless-stopped car-auction
docker run -d --env-file .env -e PORT=4001 -e SCHEDULER_ENABLED=false -p 4001:4001 --restart unless-stopped car-auction
# Nginx بالإعداد في docs/08 القسم 8
```

ثم:
1. إنشاء مستخدم المدير الأول، بكلمة مرور تحقق السياسة:
   ```bash
   node -e "import('./src/security/crypto.js').then(async c => console.log(await c.hashPassword(process.argv[1])))" 'StrongPass2026'
   ```
   ```sql
   INSERT INTO auction.users (email, full_name, password_hash, role) VALUES ('…', '…', '<hash>', 'ADMIN');
   ```
2. إدخال الموردين والموانئ الإضافية وسعر صرف اليوم.

### 1.2 النشر المتكرر بلا توقف

1. دمج الإصدار بعد نجاح CI.
2. تطبيق الهجرات المتوافقة (انظر 08 القسم 5).
3. تحديث النسخة 2 ثم التحقق من `/readyz`، ثم تحديث النسخة 1. يوزع Nginx الطلبات على السليمة.
4. **لا نشر أثناء مزاد حي.** يُراجَع جدول المزادات قبل كل نشر.
5. التراجع: إعادة تشغيل الصورة السابقة. الهجرات المتوافقة لا تحتاج تراجعًا.

## 2. خطة النشر التدريجي

| المرحلة | المدة | النطاق | معيار الانتقال للمرحلة التالية |
|---|---|---|---|
| **0. التجهيز** | أسبوع | الخوادم، النطاق، النسخ الاحتياطي واختبار استعادته، الحسابات، ترحيل بيانات السيارات الحالية (من Excel عبر استيراد CSV) | استعادة ناجحة + بيانات المخزون الحالي مطابقة لجرد فعلي |
| **1. تشغيل داخلي موازٍ** | 3 أسابيع | الموظفون فقط: التتبع، الجمارك، التكاليف. **يستمر العمل على النظام القديم بالتوازي**، وتُقارن الأرقام أسبوعيًا | تطابق تكلفة 20 سيارة عشوائية مع الدفاتر ± 0.5%؛ UAT موقّع من كل قسم |
| **2. تفعيل الربط الآلي** | أسبوعان | ربط تغذية Copart/IAAI الفعلية بعد التعاقد (استيراد CSV قبلها)، وتتبع الحاويات | 10 أيام بلا تدخل يدوي في المزامنة؛ طابور الأخطاء أقل من 2% |
| **3. مزاد تجريبي داخلي** | أسبوع | مزاد حقيقي صغير (5–10 سيارات) بمزايدين من التجار المعروفين للشركة، بمزاد هجين يدخل فيه الموظف المزايدات الحضورية | مزاد كامل بلا خلل؛ ملاحظات المزايدين مُعالجة |
| **4. فتح بوابة المزايدين** | مستمر | تسجيل العملاء وإيداع التأمين ومزادات أسبوعية | **بعد** اختبار اختراق مستقل |
| **5. التحسين** | ربع سنوي | التصدير المجدول، تطبيق جوال/إشعارات واتساب، شاشة إدارة أسعار الصرف والمستخدمين | — |

**الإيقاف الطارئ:** في أي مرحلة يمكن العودة للعمل اليدوي. البيانات تبقى في قاعدة البيانات وتُصدَّر بـ Excel.

## 3. خطة التدريب

| الجلسة | الجمهور | المدة | المحتوى | التمرين العملي (على بيئة ما قبل الإنتاج ببيانات تجريبية) |
|---|---|---|---|---|
| **1. أساسيات المنظومة** | الجميع | 60 دقيقة | الدخول، التنقل، لوحة المؤشرات، البحث والتصفية، ملف السيارة، المعرض والتكبير، المقارنة | إيجاد سيارة برقم اللوت ثم برقم الحاوية؛ مقارنة 3 سيارات |
| **2. العمليات واللوجستيات** | العمليات | 90 دقيقة | دورة الحياة والقواعد، تحديث الحالة والتعليق، تتبع الشحنات، لوحة الجمارك، الربط وطابور الأخطاء، استيراد CSV | نقل سيارة من "في الميناء" حتى "متاحة في المعرض"؛ معالجة خطأ مزامنة؛ رفع ملف CSV |
| **3. المحاسبة والتكاليف** | المحاسبة + الإدارة | 90 دقيقة | البنود والمراحل، سعر الصرف المحفوظ، الفعلي والتقديري، التكلفة المشتركة، الإلغاء، التقرير والتصدير | تسجيل فاتورة حاوية وتوزيعها؛ مطابقة تكلفة سيارة مع ملف Excel؛ إصدار PDF |
| **4. المزادات والمبيعات** | المبيعات | 90 دقيقة | إعداد المزاد واللوت، الحد الأدنى السري، التسجيل والتأمين، المزاد الهجين، المزايدة الآلية ومنع القنص، الإغلاق والفاتورة | محاكاة مزاد بين المتدربين على 3 لوتات |
| **5. الإدارة والأمان** | المدير + تقنية المعلومات | 120 دقيقة | المستخدمون والأدوار، سجل التدقيق، النسخ الاحتياطي والاستعادة، المراقبة، الأعطال الشائعة، الاستجابة للحوادث | استعادة نسخة احتياطية؛ تتبع إجراء في سجل التدقيق؛ إبطال الجلسات |
| **6. للعملاء المزايدين** | التجار والعملاء | فيديو 10 دقائق + دليل صفحتين | التسجيل، التأمين، المزايدة اليدوية والآلية، منع القنص، قراءة الرسائل | — |

**مواد التدريب:**
- دليل المستخدم: [07-user-guide.md](07-user-guide.md).
- لقطات الشاشات: [ui/](ui/).
- بطاقة مرجعية لكل دور (صفحة واحدة) تُستخرج من الدليل.
- بيئة تدريب دائمة: `npm run db:reset` يعيدها للحالة الأولى.

**قياس الفاعلية:** اختبار عملي قصير بعد كل جلسة (إنجاز التمرين دون مساعدة)، ومتابعة أسئلة الدعم في أول أسبوعين لتحديث الدليل.

**الدعم بعد الإطلاق:**
- أول أسبوعين: مستخدم خبير من كل قسم (Super user).
- قناة دعم واحدة: واتساب أو بريد.
- كل استفسار متكرر يتحول إلى سطر في "أسئلة شائعة".
